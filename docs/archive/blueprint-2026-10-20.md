# dsh-memory 总体蓝图（Blueprint）

> 状态：讨论稿 · 等待确认后进入实施
> 定位：这是项目的**总体蓝图**（愿景、方法论、结构、路线、验收）。
> 关联：`docs/architecture-v0.7.md` 是事件/情景部分的**技术附录（暂缓实施）**。
> 原则：先用科学方法把问题、证据、实验和边界写清楚，再写代码。

---

## 0. 一句话目标

为 DSH 构建一个**可观测、可评估、可回滚**的长期记忆与上下文编排层：
让 AI 在 Web、微信/IM 等不同入口和不同会话之间，**该记住的能正确取用，不该混入的不会污染上下文**，
并且每一次改进都能用数据证明有效。

---

## 1. 问题与场景

### 1.1 真实场景

- 使用者在 **Web GUI** 与 **微信 IM 入口**之间切换；IM 里换会话/换话题不方便。
- 期望：切换入口/会话时，需要时有**上下文连续性**（不必重复解释），不需要时保持**上下文隔离**（不把旧话题带进来）。
- 当前 v0.6 已解决：跨会话长期记忆的写入、整理（睡眠分级压缩）、按需/自动召回、时间与时区、DSH 模型复用、管理界面。
- 尚未解决：**上下文窗口编排**（哪些信息进入当前请求）、入口/会话切换的连续性控制、可观测的召回质量评估。

### 1.2 问题分解（从“科学问题”角度）

| 问题 | 可观测指标 | 约束 |
|---|---|---|
| 记得准吗？ | 召回命中率、被后续采纳比例、重复解释减少量 | 向量质量、整理质量 |
| 记得省吗？ | 注入 token、库条数、压缩比 | 成本、延迟 |
| 该混入吗？ | 跨话题污染率、用户纠正次数 | 上下文 API 限制 |
| 能复现/回滚吗？ | 决策日志覆盖率、开关回滚耗时 | 工程纪律 |

### 1.3 北极星指标（North Star）

> **“用户重复解释同一信息的次数下降，同时注入上下文带来的错误/污染不上升。”**

支撑指标：召回命中率、注入 token 占比、整理后信息保留率、用户纠正率、延迟/成本、功能开关回滚时间。

## 2. 方法论：用科学方法指导实践

### 2.1 核心循环（每个版本、每项功能都走一遍）

```
观察（日志/指标/用户反馈）
  → 定义问题（可度量）
  → 提出假设（可证伪）
  → 实验（特性开关/AB/回放）
  → 证据（数据、失败判据）
  → 结论（保留/调整/回滚）
  → 记录（ADR + 评估报告）
```

### 2.2 工程化原则（从“科学”落到“约束”）

| 原则 | 落地要求 |
|---|---|
| 可证伪 | 每项改动先写“假设 + 成功指标 + 失败判据”；失败判据不通过就回滚 |
| 测量先行 | 没有基线数据的优化不做；先记录再调参 |
| 可复现 | 配置、模型、时间窗、随机性可记录；重放/回放能力逐步建设 |
| 对照实验 | 新策略用开关控制（默认关），同数据 A/B 或回放对比 |
| 不确定性 | 记忆条目带来源/置信度；冲突显式化；不把“记住”当“正确” |
| 有界理性 | token、存储、延迟都有预算；默认值保守，实验值明确标注 |
| 奥卡姆剃刀 | 能用简单机制解决就不引入复杂层；事件系统等大件后置 |
| 小步可逆 | 一次只改一层；每步可单独回滚；避免一次性重写 |
| 记录决策 | 重要设计写入 ADR（decision record），包括被否决的方案与理由 |

### 2.3 反模式（明确不做）

- 凭“感觉变好了”调参、无指标大重构；
- 把“记忆条数/库大小”当成质量；
- 用“像人脑”作为正确性论据；
- 一次性重写、无开关、无回滚；
- 把不可验证的哲学口号直接写进架构约束。

> 说明：这里不选某个哲学流派作为教条；我们采用**科学方法论本身**（观察—假设—实验—证据—修正），
> 其中“可错论/可证伪/边界理性/系统反馈”是指导工程实践的工作原则。

## 3. 总体架构蓝图

### 3.1 分层视图（实线=已实现，虚线=未来）

```
┌─────────────────────────────────────────────────────────────┐
│ 入口与适配：Web GUI / 微信 IM / 其他通道（DSH Session）        │
└────────────────────────────┬────────────────────────────────┘
                             │ session events / turns
┌────────────────────────────▼────────────────────────────────┐
│ ① 观察与采集（已实现）                                        │
│   自动记录（turn/图片/工具）、来源与时间戳、DSH session 映射   │
├─────────────────────────────────────────────────────────────┤
│ ② 记忆基底（已实现）                                          │
│   Belief Store（Qdrant 向量+payload）、层级 L0-L3、批次任务板   │
├─────────────────────────────────────────────────────────────┤
│ ③ 巩固与维护（已实现）                                        │
│   睡眠整理（按天→7天→30天）、去重/过期/容量、自动维护           │
├─────────────────────────────────────────────────────────────┤
│ ④ 取用与注入（已实现）                                        │
│   自动召回、memory 工具、时间/时区、预算与超时                 │
├─────────────────────────────────────────────────────────────┤
│ ⑤ 上下文编排（未来·实验）                                     │
│   Episode/时间窗、E1 召回限定 → E2 边界压缩 → （事件驱动）      │
├─────────────────────────────────────────────────────────────┤
│ ⑥ 模型路由（已实现）                                          │
│   DSH 模型（ctx.llm，默认）/ 自定义 provider 回退              │
├─────────────────────────────────────────────────────────────┤
│ ⑦ 治理与可观测（规划中）                                      │
│   指标、召回决策日志、实验开关、评估报告、ADR、回滚            │
├─────────────────────────────────────────────────────────────┤
│ ⑧ 事件驱动层（暂缓·未来）                                     │
│   事件日志/投影/情景索引，用于跨入口上下文切换控制             │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 数据流与反馈

```
会话事件 → 观察/提取 → Belief(带证据) → 整理/压缩 → 检索/预算 → 注入上下文 → 模型
                                   ↑                              │
                                   └──── 召回决策日志/指标 ←──────┘
```

- **前向**：事件 → 信念 → 整理 → 取用；
- **反向**：决策与效果 → 指标 → 假设 → 策略调整（开关/超参/模型）。

## 4. 领域概念（蓝图级，不承诺立即实现）

| 概念 | 定义 | 当前状态 | 未来用途 |
|---|---|---|---|
| Observation / Event | 会话中发生的事实（消息、图片、工具调用） | 通过 DSH 事件监听采集 | 事件日志、重放、情景 |
| Belief / Memory | 对事实的压缩解释（摘要/事实/偏好/事件） | Qdrant 记忆条目 | 置信度、证据链、撤回 |
| Episode / 情景 | 同一会话内连续时间段 | 未实现 | 上下文窗口单位 |
| Policy / 策略 | 取用范围、预算、整理节奏、实验开关 | 现有配置 | 情景/上下文策略 |
| Decision Log | 一次召回/注入/整理决策 | 部分统计 | 评估与复现 |
| Experiment | 带假设与失败判据的开关实验 | 部分开关 | 科学迭代 |

> 事件溯源（event sourcing）是未来**可选**实现手段，不是本蓝图的前置要求；
> 在没有 DSH 上下文裁剪 API 之前，不为了“事件驱动”而复制一份会话日志。

## 5. 上下文编排蓝图（未来·实验）

### 5.1 为什么需要

- IM 入口切换会话不方便 → 需要“记忆连续但上下文可控”；
- 当前自动召回是“按相关性取用”，没有“按时间连续性取用”的边界；
- 目标行为（用户 v0.7 需求）：启用后，同一会话的上下文只使用**当前连续时间段**内的信息（默认 15 分钟边界，或未来 AI 主动触发分割）。

### 5.2 技术现实（必须诚实）

DSH 0.2.1 的插件 API 无法直接裁剪模型请求的完整历史：
`agent/pre-step` 只替换本步进入消息，`agent/request` 只换模型配置，session projection 只投影插件自有事件。
因此分三层推进（用户已选 E1 → E2）：

| 层级 | 行为 | 风险 | 状态 |
|---|---|---|---|
| **E1** | 召回/情景摘要限定当前 Episode/时间窗；不碰 DSH 历史 | 低 | 蓝图确认，待排期 |
| **E2** | 边界处调用 compaction 压缩旧上下文（摘要），再注入边界提示 | 中（需 spike） | 待验证 DSH 能力 |
| E3 | 每个 Episode = 新 DSH 会话（真隔离，UX 改变） | 高 | 不采用为默认 |
| E4 | 等待 DSH 上游 context policy API | 依赖上游 | 长期 |

### 5.3 IM/微信入口的上下文连续性（待确认）

事件驱动系统最初动机是“换入口/换会话时控制上下文”，需明确目标体验（三选一或组合）：

- **A 共享记忆，不共享上下文**：不同入口共用长期记忆；上下文各自独立，需要时用 `memory_search`（最安全）；
- **B 自动接续最近情景摘要**：新入口/新会话自动注入最近 Episode 摘要（连续性好，可能串话题）；
- **C 手动接续/隔离**：提供“接续最近上下文 / 开新情景”按钮或命令（折中）。

> 事件驱动层（事件日志/投影/情景索引）是为 B/C 打基础，**暂缓实施**；
> 先用 E1 验证“情景范围内的召回”是否足够，再决定是否引入事件层。

### 5.4 默认关闭

- `experimentalEpisodeContextEnabled=false`；
- 关闭时行为与 v0.6 完全一致；
- 开启时先只影响召回/摘要注入，不改变 DSH 历史。

## 7. 数据与存储蓝图

| 数据 | 介质 | 保留/隐私 | 说明 |
|---|---|---|---|
| 记忆条目 | Qdrant | 可删除/导出；TTL/容量 | 当前 19 条 legacy |
| 整理任务板 | 本地 JSON | 最近 600 批 | 5 位批号 |
| 睡眠/整理历史 | 本地 JSON（汇总） | 40 条 | 已在状态页 |
| 召回决策 | 本地 JSONL（未来） | 轮转 30 天 | 不含正文，只含 query/候选/选择 |
| 事件日志 | 暂缓 | — | 不复制会话全文 |
| 配置与模型映射 | DSH settings/插件配置 | 用户可控 | 实验开关显式标注 |

原则：**数据最小化**；能存引用就不复制正文；所有派生物可重建；删除可传播。

## 8. 模型与依赖边界

- 聊天类功能（整理/图片概览/未来情景摘要）优先复用 **DSH 已配置模型**（`ctx.llm`），Key 由 DSH 管理；
- 自定义 provider 作为回退；
- 嵌入模型无法来自 DSH（无 embedding API），由插件 provider 决定并绑定 Qdrant 维度；
- 所有模型调用记录 provider/model/usage/latency/结果，进入指标。

## 9. 质量、测试与评估蓝图

- **测试分层**：单元 / 集成（真实 Qdrant+mock DSH）/ 浏览器 / 回放；
- **测试即证伪**：每项实验先定义失败判据，测试覆盖失败路径（超时、模型失败、空库、冲突）；
- **指标面板**（规划）：召回命中/采纳、注入 token、整理压缩率、延迟、错误率、开关状态；
- **评估节奏**：每次发布附“假设-指标-结论”一页报告；未达预期回滚并记录原因。

## 11. 风险登记册

| 风险 | 影响 | 缓解 |
|---|---|---|
| DSH 无上下文裁剪 API | E2 不可行，E1 效果有限 | 明确分阶段；E2 先 spike；不承诺超出 API 的能力 |
| IM 入口会话映射不稳定 | 跨入口连续性差 | 先做记忆共享（A），B/C 需事件层再评估 |
| 指标数据不足 | “科学”变口号 | P1 先补决策日志与基线 |
| 事件日志重复/隐私 | 存储与信任风险 | 暂缓事件层；未来只存引用+摘要 |
| 实验功能影响主流程 | 用户困扰 | 默认关、可视化状态、一键回滚 |
| 重构范围失控 | 回归/延期 | 分层迁移、一次一层、旧行为作为基线测试 |
