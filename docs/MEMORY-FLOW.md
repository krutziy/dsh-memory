# 记忆处理流程（v0.8 · 记忆片段）

> 状态：**已实现（v0.8.0）**。
> 队列字段、状态机、编号规则、迁移与 UI 见 [`QUEUE.md`](QUEUE.md)；本文描述完整记忆生命周期。
> 术语：**片段**（记忆单位）/ **事件**（一次会话在同一天的经历）/ **合并**（压缩成更少更抽象的片段）/
> **编号**（待整理批次在队列里的临时凭证；片段固化后编号回收、记忆上不再带编号）。

---

## 0. 指导原则（功能仿生，不是生物复制）

我们模仿人脑的**功能轮廓**，不假装复刻生物机制；每个参数都必须可测量、可证伪、可回滚。

| 人脑现象 | 工程映射 | 对流程的影响 |
|---|---|---|
| 编码需要注意/显著性 | 捕获时评估 `importance`（显式保存 > 偏好/事实 > 闲聊） | 高重要性片段更容易被召回 |
| 短时记忆容量有限 | 上下文预算、topK、懒加载 | 每轮只注入少量 |
| 睡眠巩固 | 睡眠整理：事件 → 周 → 长期，逐级合并 | 片段更少、更抽象、细节更模糊 |
| 遗忘曲线 | `freshness = exp(-age/τ_level)` | 同等相似度下，旧片段更难被召回 |
| 间隔/复述效应 | 有效复述强化（B/C/D 类） | 被反复用到的片段更抗遗忘 |
| 线索依赖回忆 | 查询 + 时间上下文 | 不是“全库模糊搜索” |
| 情节记忆 → 语义记忆 | 事件片段 → 周片段 → 长期片段；编号随之消失 | 不再保留“当时属于哪次会话” |
| 重构而非回放 | 注入整理后的要点，并注明时间/置信度 | 不假装精确复述原文 |
| 适应性遗忘 | TTL/容量/低强度淘汰 | 遗忘是特性不是 bug |
| 元认知 | `confidence`、来源、时间标注 | 模型知道“这条记忆有多可靠” |

> 哲学立场：**功能主义 + 可错论 + 有限理性**。记忆是“当前最优的重构”，不是绝对档案；
> 遗忘和压缩是资源约束下的适应，不是失败。

## 1. 三层东西（不再把“会话”当记忆容器）

| 层 | 归属 | 是什么 | 生命周期 |
|---|---|---|---|
| **会话** | DSH 宿主 | 一次对话经历（消息、模型上下文、工作目录） | DSH 管理，可删除/压缩/新开 |
| **片段** | 插件 | Qdrant 里一个点：文本要点/图片概览 + 向量 + payload | 插件维护，跨会话存活，可合并/遗忘 |
| **批次** | 插件 | 整理队列里的一组片段（统一编号、状态、来源/产出） | 等待整理期间存在；固化后编号回收 |

- 会话是**经历的来源**，不是记忆的家；`sessionId` 只用于采集时划分事件批次，**不写入记忆**。
- 事件 = 同一会话在同一天的活动片段；同一天可以有多段事件。
- 整理完成后，“这次经历属于哪次会话”就淡去了——这正是情节记忆变成语义记忆的过程。

## 2. 主流程（全局）

```
DSH 会话事件（用户消息 / 助手回复 / 图片）
        │
        ▼

│ ① 编码 Encode                                        │
│  关闭 / 睡眠中 / 子代理未开启 → 丢弃                  │
│  评估 importance；确定所属事件批次（会话 × 日期）      │
│  → 原始片段（level=0，batch=待整理编号）              │
└───────────────────┬──────────────────────────────────┘
                    │ 清洗·脱敏·截断·内容哈希去重
                    ▼
┌──────────────────────────────────────────────────────┐
│ ② 存储 Store                                         │
│  文本嵌入 → Qdrant；图片只存一句概览；不存 sessionId/cwd│
└───────────────────┬──────────────────────────────────┘
                    │
        ┌───────────┴────────────┐
        ▼                        ▼
┌──────────────────┐    ┌────────────────────────────┐
│ ③ 回忆 Recall     │    │ ④ 巩固 Consolidate          │
│  线索 → 候选      │    │  睡眠：事件→周→长期 合并     │
│  动态相关度门控    │    │  编号只在待整理期间存在      │

└────────┬─────────┘    └───────────┬────────────────┘

┌──────────────────────────────────────────────────────┐
│ ⑤ 遗忘 Forget                                        │
│  TTL / 容量 / 低强度淘汰 / 用户删除 / 冲突修正        │
└──────────────────────────────────────────────────────┘
```

## 3. 编码与写入

```
turn/start → 建立缓冲（用户文本 / 助手文本 / 图片引用）
用户消息 → 只收 source=user；图片块单独记录
助手回复 → 取最后一条助手文本
turn/end(completed) → 汇总候选
        │
        ▼
{自动记录开启？} ─否─▶ 丢弃
{正在睡眠？} ─是─▶ 丢弃（zzzZZ 不入库）
{子代理未开启 includeSubagents？} ─是─▶ 丢弃
{长度 ≥ captureMinChars？} ─否─▶ 丢弃
        │是
        ▼
[清洗] 去空白 / redactSecrets / 截断
[重要性] importance ∈ [0,1]（显式保存 1.0；偏好/身份/决定 0.7~0.9；事实 0.5~0.8；闲聊 0.2~0.4）
[置信度] confidence（写入默认 0.7；显式保存 0.9）
        │
        ▼
[事件批次] 当天该会话第一次写入时创建批次：
  稳定键 dayKey#seq；显示编号 5 位；状态 collecting
        │
        ▼
(原始片段 L0：level=0, batch=编号, ts, importance, confidence,
  anchorTs=消息时间, source=user/assistant)
        │
        ├─ 文本：embedding（当前激活插件 provider）→ 维度校验
        └─ 图片：caption → DSH 视觉模型默认 / 自定义回退；失败 → 占位记录
        │
        ▼
Qdrant upsert：id = hash(kind|text)（同文覆盖去重）
```

> **记忆里不存什么**：`sessionId`、`cwd`、原始图片、完整对话。会话只用来划分事件；
> 长期记忆保存的是重构后的要点。

## 4. 回忆流程：动态相关度

### 4.1 五步回忆模型

```
用户新消息 → agent/pre-step 第一步
        │
        ▼
{睡眠整理中？} ─是─▶ 回 zzzZZ + 排队；整理结束后 followup
        │否
        ▼
1) 线索构造 Cue
   查询 = 最后一条真实人类消息
   上下文 = 当前时间 / 时区（不再使用会话 id）
        │
        ▼
2) 候选生成 Candidates
   query embedding → Qdrant topN（N=20~50，先宽后严）
   排除 enhanced 副本；排除最近 N 分钟自动记录的对话片段（默认 10 分钟）
        │
        ▼
3) 动态相关度门控 Dynamic Gate（越久越严格）
   ageDays = now − anchorTs（内容发生时间，不是整理写入时间）
   freshness = exp(-ageDays / τ_level)
   required  = baseMinScore + strictness × (1 − freshness)
   effective = sim + importanceBoost + rehearsalBoost + confidenceBoost
   {effective ≥ required？} ─否─▶ 丢弃
        │是
        ▼
4) 排序与预算 Rank & Budget
   rank = sim × (0.5 + 0.5×freshness)
          + 0.15×importance + 0.10×rehearsal + 0.05×confidence
   近重复去重（>0.95 只保留 rank 高者）
   取 topK、按 recallMaxChars 裁剪
        │
        ▼
5) 重构式注入 Reconstruct
   当前时间 + 时区
   每条：发生时间 · 相对年龄 · 类型 · 置信度
   头部声明：记忆可能不完整，冲突时以当前对话为准
```

### 4.2 分层遗忘速度 τ

| 层级 | 产物 | τ（默认） |
|---|---|---|
| L0 | 原始片段 | 7 天 |
| L1 | 事件片段 | 30 天 |
| L2 | 周片段 | 180 天 |
| L3 | 长期片段 | 365 天 |

越久的要求相关度越高；但 importance、有效复述、置信度可以抵消时间惩罚（有上限，防止老记忆永远召不回）。
所有参数在设置页可调，`recallAgeGateEnabled=false` 可一键回退旧的固定阈值公式。

### 4.3 复述分类（A-E）

| 类型 | 场景 | 权重 | 是否影响排序 |
|---|---|---|---|
| A 被动曝光 | 自动召回注入 | 不计 | **否**（只记 `exposureCount`，防自我强化） |
| B 主动检索 | `memory_search` 命中 | 1.0 | 是 |
| C 自然复述 | 用户再次提到同一事实 | 1.5 | 是 |
| D 用户确认 | 明确认可召回内容 | 2.0 | 是（confidence +0.10） |
| E 用户纠正 | 指出记忆有误 | 1.0 | 是（confidence −0.20，标记 needsReview） |

```
rehearsalBoost = w_hit × min(1, ln(1+effectiveHits)/ln(11))
effectiveHits 按 τ_rehearse（默认 90 天）衰减；accessEvents 只保留最近 20 条
```

### 4.4 复述驱动的再巩固

- C/D/E 发生时更新计数、`lastAccessAt`、`corrections`；
- 被纠正的记忆标记 `needsReview=true`，下次睡眠整理优先修订或提示用户确认；
- 自动召回只影响排序，不直接改写记忆内容（避免模型自我编辑）。

## 5. 睡眠巩固流程（记忆怎么被合并）

```
每 30 秒 tick → {开启? 到点? 今天没整理过? 空闲?}
  │ 否 → 记录跳过原因，15 分钟后重试
  │ 是
  ▼
[入睡] sleeping=true（新消息回 zzzZZ 并排队）
  │
  ▼
整理队列 = 批次台账（queue.json），编号只在待整理期间存在
  0) 把没有批次的原始片段（手动保存/旧数据）按天归入 #misc 批次
  1) 封批：今天之前的 collecting 批次 → sealed
  2) L1：每个事件批次 → 事件片段
       写 L1（level=1, batch=事件编号, anchorTs=当天起点, importance/confidence 继承）
       删除原文；批次 → waiting，等到“周末结束后 level2AfterDays 天”
  3) L2：到期事件批次按周分组 → N:1 合并成周片段
       写 L2（level=2, batch=新编号, anchorTs=周一零点）；删除 L1；来源批次 merged（编号回收）
       新批次 → waiting，等到“月末结束后 level3AfterDays 天”
  4) L3：到期周批次按月分组 → N:1 合并成长期片段
       写 L3（level=3, batch 清空, anchorTs=月初零点）；删除 L2；来源批次 merged
       新批次 → final（编号回收，不再压缩）
  5) 维护（TTL/容量/相似去重/索引检查）→ 保存历史 → 醒来 followup 排队消息
        │
        ▼
失败：只影响该批次（attempts+1，failed），下个睡眠窗口重试；不阻塞其他批次
```

- **编号生命周期**：collecting → sealed → running → waiting → merged/final。
  编号在 merged/final 时回收；记忆上的 `batch` 字段在 final 产物上为空。
- **失败不丢数据**：写入成功才删来源；删除失败保留原文，下一轮 idSeed 相同（幂等写入）再重试。
- 整理后的记忆 `anchorTs` 指向内容发生时间（当天/周/月起点），年龄才反映真实记忆年龄。
- 实验插槽：事件合并（整理时检索相似片段作参考）、增强记忆（保留 L1 副本 N 天）默认关闭。

## 6. 单条记忆生命周期

```
原始片段 L0（τ=7d，带事件编号）
  │ 睡眠（事件内合并）
  ▼
事件片段 L1（τ=30d，带事件编号，等待周合并）
  │ 周末结束后 7 天
  ▼
周片段 L2（τ=180d，带周编号，等待月合并）
  │ 月末结束后 30 天
  ▼
长期片段 L3（τ=365d，**不再带编号**）
  │
  ├─ 有效复述：主动检索/自然复述/确认 → effectiveHits↑ → 更抗遗忘
  ├─ 被动曝光：只记 exposureCount，不影响排序
  ├─ 被纠正：confidence↓、needsReview，下次整理再巩固
  ├─ 用户删除 / TTL / 容量 / 低强度淘汰 → 删除
  └─ 冲突 → 保留双方并标记，整理时裁决
```

## 7. 模型使用点

| 环节 | 模型 | 来源 | 失败时 |
|---|---|---|---|
| 文本嵌入 | 嵌入模型 | 插件当前 provider | 写入失败 |
| 图片概览 | 视觉/对话 | DSH 模型默认 / 自定义回退 | 占位记录 |
| 记忆合并 L1/L2/L3 | 对话模型 | DSH 模型默认 / 自定义回退 | 规则压缩兜底 |
| 事件合并[实验] | 对话模型 | 同上 | 跳过事件摘要 |

> 嵌入模型唯一无法来自 DSH（DSH 无 embedding 接口）。

## 8. 可观测与实验

| 指标 | 用途 |
|---|---|
| 召回命中率 / 用户纠正率 | 验证动态门槛是否提高准确率 |
| 各年龄段的召回占比 | 验证“越久越严格”是否按预期生效 |
| 复述强化后命中变化 | 验证间隔/复述效应（分 B/C/D 类统计） |
| 被动曝光 vs 主动复述比例 | 检查是否出现注入自我循环 |
| 队列各状态批次数量 / 到期时间 | 观察整理是否按节奏推进 |
| 每批输入→产出条数 / 失败重试 | 巩固质量与稳定性 |
| A/B：旧公式 vs 动态公式 | 开关控制，默认开新公式可在配置关掉 |

**实验纪律**：每个参数（τ、strictness、权重）先写假设与失败判据，再用决策日志回放评估；不达预期就回滚。
**默认策略**：新公式默认开启（可一键回退旧公式），参数保守；写入/整理流程不变。

## 9. 已确认决策与不涉及

### 已确认

- 功能仿生方向（不是生物复制；参数可测量、可回滚）；
- 心智模型：DSH 是持续存在的人；会话是经历；记忆是经历重构后的片段；片段会随时间衰减；
- 事件 = 会话 × 日期；L1 事件片段 → L2 周片段 → L3 长期片段，后两层 N:1 合并；
- 批次编号只是“待整理凭证”：只存在于等待/执行期间，固化后回收，记忆上不再保留；
- 记忆里不存 `sessionId`/`cwd`；用“最近 N 分钟时间窗”替代“排除当前会话”；
- 先写清全流程与队列设计，再实现功能。

### 不涉及（未来）

- 微信/IM 入口、事件驱动、AI 主动情节分割；
- 跨设备同步、多用户记忆隔离；
- 历史会话全量回填（需另行评估成本与隐私）。
