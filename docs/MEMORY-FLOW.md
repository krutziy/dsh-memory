# 记忆处理流程（文本流程图 · v3 完整设计）

> 状态：**已实现（v0.7.0）** · 文本流程与动态相关度模型
> 实现说明：动态召回公式、复述分类 A-E、旧记忆字段迁移已落地；参数在设置页可调，可一键回退旧公式。
> 本版变化：用“功能仿生”的哲学原则重排记忆生命周期；召回引入**动态相关度**——离现在越久，要求的相关度越高（但重要/常被回忆的记忆可以抵消时间惩罚）；**复述强化按情况分类**（被动曝光≠主动复述）。
> 已确认：功能仿生方向、动态门槛+分层遗忘速度、内容发生时间锚点、先完成完整设计再做功能。
> 不涉及微信/IM、不涉及未来实验特性；`[未来]`/`[实验]` 仅预留插槽。

## 0. 指导原则（功能仿生，而非生物复制）

我们模仿人脑的**功能轮廓**，不假装复刻生物机制；每个参数都必须可测量、可证伪、可回滚。

| 人脑现象 | 工程映射 | 对流程的影响 |
|---|---|---|
| 编码需要注意/显著性 | 捕获时评估 `importance`（显式保存 > 偏好/事实 > 闲聊） | 高重要性记忆召回更容易 |
| 短时记忆容量有限 | 上下文预算、topK、懒加载 | 每轮只注入少量 |
| 睡眠巩固 | 睡眠整理：L1 按天 → L2 7 天 → L3 30 天 | 记忆被压缩、稳定、去细节 |
| 遗忘曲线 | `freshness = exp(-age/τ_level)`，越久衰减越多 | 同等相似度下，旧记忆更难被召回 |
| 间隔/复述效应 | `recallHits`、`lastAccessAt` 强化记忆 | 被反复用到的记忆更抗遗忘 |
| 线索依赖回忆 | 查询 + 当前会话/工作区/时间上下文共同作为线索 | 不是“全库模糊搜索” |
| 重构而非回放 | 注入的是整理后的 Belief（摘要/事实），并注明时间/不确定性 | 不假装精确复述原文 |
| 干扰与冲突 | 近重复压重、冲突标记 | 同一主题不重复注入 |
| 适应性遗忘 | TTL/容量/低强度淘汰 | 遗忘是特性不是 bug |
| 元认知 | `confidence`、来源、时间标注 | 模型知道“这条记忆有多可靠” |

> 哲学立场：**功能主义 + 可错论 + 有限理性**。记忆是“当前最优的重构”，不是绝对档案；
> 遗忘和压缩是资源约束下的适应，不是失败。

## 2. 编码与写入（一条记忆怎么产生）

```
turn/start → 建立缓冲（用户文本 / 助手文本 / 图片引用）
用户消息 → 只收 source=user；图片块单独记录
助手回复 → 取最后一条助手文本
turn/end(completed) → 汇总候选
        │
        ▼
{自动记录开启？} ─否─▶ 丢弃
{正在睡眠？} ─是─▶ 丢弃（zzzZZ 不入库）
{子代理未开启 includeSubagents？} ─是─▶ 丢弃
{长度 ≥ captureMinChars？} ─否─▶ 丢弃
        │是
        ▼
[清洗] 去空白 / redactSecrets / 截断
[重要性评估] importance ∈ [0,1]
   - 用户显式 memory_save = 1.0
   - 偏好/身份/决定/项目 = 0.7~0.9（模型/规则判断）
   - 事实/任务 = 0.5~0.8
   - 普通闲聊/寒暄 = 0.2~0.4
[置信度] confidence（写入时默认 0.7；显式保存 0.9）
        │
        ▼
(原始记忆 L0：level=0, batch='', ts, importance, confidence,
 anchorTs=消息时间, source=user/assistant, sessionId, cwd)
        │
        ├─ 文本：embedding（当前激活插件 provider）→ 维度校验
        └─ 图片：{imageMode} caption → DSH 视觉模型默认 / 自定义回退
                 └─ 失败 → 占位记录
        │
        ▼
Qdrant upsert：id = hash(kind|text)（同文覆盖去重）
```

> 这一段是“注意/编码强度”的落地：不是所有对话等权；显式保存、偏好、决定天然更容易被回忆。

## 3. 回忆流程：动态相关度（本版核心）

### 3.1 五步回忆模型

```
用户新消息 → agent/pre-step 第一步
        │
        ▼
{睡眠整理中？} ─是─▶ 回 zzzZZ + 排队；整理结束后 followup
        │否
        ▼
1) 线索构造 Cue
   查询 = 最后一条真实人类消息
   上下文 = 当前会话 / 工作区 / 时间 / 时区
        │
        ▼
2) 候选生成 Candidates
   query embedding → Qdrant topN（N=20~50，先宽后严）
   作用域过滤：global / workspace / session
   排除：enhanced 副本（不参与自动召回）
        │
        ▼
3) 动态相关度门控 Dynamic Gate（越久越严格）
   ageDays = now − anchorTs（用内容发生时间，不用整理写入时间）
   freshness = exp(-ageDays / τ_level)
   required  = baseMinScore + strictness × (1 − freshness)
   effective = sim + importanceBoost + rehearsalBoost + confidenceBoost
   {effective ≥ required？} ─否─▶ 丢弃
        │是
        ▼
4) 排序与预算 Rank & Budget
   rank = sim × (0.5 + 0.5×freshness)
          + 0.15×importance + 0.10×rehearsal + 0.05×confidence
   近重复去重（>0.95 只保留 rank 高者）
   取 topK、按 recallMaxChars 裁剪
        │
        ▼
5) 重构式注入 Reconstruct
   当前时间 + 时区
   每条：发生时间 · 相对年龄（如“3 天前”）· 类型 · 置信度
   头部声明：记忆可能不完整，冲突时以当前对话为准
   → 注入 source=long-term-memory
        │
        ▼
   复述强化：被注入的记忆 recallHits += 1，lastAccessAt = now
   [未来] 召回决策日志：query/候选/每项分数/最终注入
```

### 3.2 动态相关度公式（草案）

```text
# 年龄（内容时间）
ageDays = max(0, (now - anchorTs) / 1 天)
  anchorTs = memory.validFrom ?? memory.dayRange.from ?? memory.ts

# 时间衰减：不同层级有不同的“遗忘速度”
freshness = exp(-ageDays / τ_level)
  τ(L0 原始)  = 7   天   → 快忘
  τ(L1 日摘要)= 30  天
  τ(L2 周摘要)= 180 天
  τ(L3 长期)  = 365 天   → 巩固后的记忆更稳定

# 动态门槛：越久越严格
required = clamp(
  baseMinScore + strictness × (1 - freshness),
  baseMinScore,
  maxRequired
)

# 记忆强度补偿（重要/有效复述/高置信度可以“抗遗忘”）
importanceBoost = w_imp  × (importance - 0.5)     # -0.5~+0.5
rehearsalBoost  = w_hit  × min(1, ln(1+effectiveHits)/ln(11))
confidenceBoost = w_conf × (confidence - 0.5)
effective = sim + importanceBoost + rehearsalBoost + confidenceBoost

# 有效复述：不是所有“被看到”都算强化（详见 3.4 分类）
# effectiveHits = Σ 分类权重 × exp(-(now - 事件时间)/τ_rehearse)
# 被动曝光（自动召回注入）不计入 effectiveHits，只记入 exposureCount 供评估用

# 通过条件
effective >= required
```

默认参数（可实验调整，全部进配置/实验开关）：

| 参数 | 默认 | 说明 |
|---|---|---|
| `baseMinScore` | 0.42 | 新记忆的基础相关度门槛 |
| `strictness` | 0.35 | 越久越严格的程度（0=旧完全等价） |
| `maxRequired` | 0.90 | 门槛上限，防止永远召不回 |
| `w_imp` | 0.20 | 重要性补偿权重 |
| `w_hit` | 0.15 | 复述补偿权重（对数增长） |
| `w_conf` | 0.10 | 置信度补偿权重 |
| `τ` 四档 | 7/30/180/365 天 | 原始/日/周/长期记忆的遗忘速度 |
| `τ_rehearse` | 90 天 | 复述事件的“记忆效力”衰减时间 |
| `effectiveHits` 权重 | 见 3.4 | 主动检索 1.0 / 自然复述 1.5 / 用户确认 2.0 / 纠正 1.0 / 被动曝光 0 |

**效果直觉**：
- 昨天的高相似记忆：freshness≈0.87，required≈0.47，容易通过；
- 30 天前的原始记忆：freshness≈0.014，required≈0.77，需要很强语义匹配 + 重要性/复述才通过；
- 30 天前的 L3 长期记忆：freshness≈0.92，required≈0.45，仍可被召回（巩固使其稳定）；
- 显式保存的重要事实：importanceBoost 可抵消部分时间惩罚。

### 3.3 回忆模式的严格度（同一套公式，不同参数）

| 模式 | 触发 | baseMinScore | strictness | topK | 说明 |
|---|---|---|---|---|---|
| 自由回忆（自动召回） | 每轮 pre-step | 0.42 | 0.35 | 3 | 严格、少而准 |
| 线索回忆（memory_search 工具） | 模型主动查 | 0.30 | 0.20 | 5~10 | 用户/模型主动提供线索，可放宽 |
| 再认（管理页浏览/列表） | 用户浏览 | 无门槛 | — | 分页 | 按时间/层级展示 |

### 3.4 复述强化：分类讨论（被动曝光 ≠ 主动复述）

人脑里“看到过”不等于“记住了”：被动曝光只有微弱启动效应，主动检索、间隔复述、确认/纠正才会真正强化记忆。
因此把“强化事件”分成五类，分开计数、分开影响：

| 情况 | 触发方式 | 权重 | 对记忆的影响 | 说明 |
|---|---|---|---|---|
| A. 被动曝光 | 自动召回被注入（未被使用） | **0（仅记录）** | `exposureCount++`、`lastExposedAt`；不进入 `effectiveHits`，不影响排序 | 避免“注入→自我强化→更容易注入”的反馈偏置；仅用于评估“曝光量” |
| B. 主动线索检索 | 模型主动调用 `memory_search` 并命中 | 1.0 | `effectiveHits += 1.0`；`lastAccessAt=now`；进入排序补偿 | 主动检索是最接近“成功回忆”的强化 |
| C. 自然复述 | 用户再次提及同一事实/主题（新 L0 与信念相似度 ≥ 0.85，且 kind 匹配） | 1.5 | `effectiveHits += 1.5`、`lastAccessAt`；`confidence += 0.02`（封顶 0.95） | 间隔复述效应；由写入链路异步判定 |
| D. 用户确认 | 用户明确说“对/没错/是的/记住这个”等（规则命中，后续可加模型判断） | 2.0 | `effectiveHits += 2.0`；`confidence += 0.10`（封顶 0.95） | 最强的正向强化 |
| E. 用户纠正 | 用户说“不对/不是/应该是…/改一下”等 | 1.0 | `effectiveHits += 1.0`；`confidence -= 0.20`（下限 0.05）；标记 `needsReview/conflictOf` | 纠正是“再巩固”的入口：下次整理或显式保存时更新内容 |
| F. 显式保存 | 用户 `memory_save` / 管理页添加 | 编码强化 | `importance=1.0, confidence=0.9`；不记入复述 | 这是编码强度，不是回忆强度 |
| G. 睡眠整理 | L1/L2/L3 生成 | 稳定化 | 层级 τ 变长（巩固后的记忆更抗遗忘）；不记入复述 | 与 A-E 无关，是“离线巩固” |

有效复述计算：

```text
effectiveHits = Σ_type ( weight[type] × exp(-(now - eventAt)/τ_rehearse) )
  τ_rehearse = 90 天（可配）
  weight = B 1.0 / C 1.5 / D 2.0 / E 1.0；A 不计入
  accessEvents 只保留最近 20 条（oldest 淘汰）；exposureCount 单独存
rehearsalBoost = w_hit × min(1, ln(1+effectiveHits)/ln(11))
```

为什么这样分类：
- **被动曝光不强化**：否则自动召回会自我循环（越注入越容易召回），偏离“准确”目标；
- **主动检索/自然复述/确认**：衰减慢、叠加形成“间隔效应”；
- **纠正**：不是简单降权，而是触发再巩固（先标记冲突，下一次整理或用户显式保存时修正内容）；
- **显式保存**：归入编码强度 `importance`，避免与回忆强度混淆。

### 3.5 复述驱动的再巩固（reconsolidation）

- 当 C/D/E 发生时，除了更新计数，还记录 `lastAccessAt`、`corrections`；
- 若某条记忆被纠正，标记 `needsReview=true`；下次睡眠整理优先把它与相邻事实一起交给整理模型修订（或提示用户确认）；
- 自动召回只影响排序，不直接改写记忆内容（避免模型自我编辑）；内容修订只发生在整理/显式保存链路。

## 4. 睡眠巩固流程（记忆怎么被压缩）

```
每 30 秒 tick → {开启? 到点? 今天没整理过? 空闲?}
  │ 否 → 记录跳过原因，15 分钟后重试
  │ 是
  ▼
[入睡] sleeping=true（新消息回 zzzZZ 并排队）
  │
  ▼
任务列表（consolidation.json，5 位随机批号，pending 唯一）
  L1：今天之前的 L0 按天分组 → 每批读原文 → 模型输出 summary+facts
      → 写 L1（level=1, batch, anchorTs=当天起点, importance 继承/重估）
      → 删原文 → 登记 pending（7 天后可 L2）
  L2：到期的 L1 批次 → 再压缩 → 写 L2 → 删 L1 → done（30 天后可 L3）
  L3：到期的 L2 批次 → 再压缩 → 写 L3 → final
  {增强记忆[实验]?} 额外 L1 副本保留 N 天，仅按需/事件召回，到期删除
  {事件合并[实验]?} 跨天相似记忆作为参考，生成 kind=event（可召回）
  │
  ▼
维护（TTL/容量/相似去重/索引检查）→ 保存历史 → 醒来 followup 排队消息
```

**注意**：巩固后的记忆 `anchorTs` 指向内容发生时间（如当天/当周起点），而不是整理写入时间——
这样“年龄”反映的是记忆内容的真实年龄，动态相关度才合理。

## 5. 单条记忆生命周期

```
L0 原始（快忘，τ=7d）
  │ 睡眠按天
  ▼
L1 日摘要（τ=30d，importance/confidence 继承或重估）
  │ 7 天后
  ▼
L2 周压缩（τ=180d）
  │ 30 天后
  ▼
L3 长期摘要（τ=365d，final）
  │
  ├─ 有效复述：主动检索/自然复述/确认 → effectiveHits↑ → 排序/门槛补偿 → 更抗遗忘
  ├─ 被动曝光：只记录 exposureCount，不影响排序（避免自我强化）
  ├─ 被纠正：confidence↓、needsReview，下次整理再巩固
  ├─ 用户删除 / TTL / 容量 / 低强度淘汰 → 删除
  └─ 冲突 → 保留双方并标记，整理时裁决

旁路：
- 事件记忆[实验]：跨天相似事件合并，kind=event，参与召回
- 增强记忆[实验]：L1 副本（enhanced），不参与自动召回/不再整理，到期删除
```

## 6. 模型使用点

| 环节 | 模型 | 来源 | 失败时 |
|---|---|---|---|
| 文本嵌入 | 嵌入模型 | 插件当前 provider | 写入失败 |
| 图片概览 | 视觉/对话 | DSH 模型默认 / 自定义回退 | 占位记录 |
| 记忆整理 L1/L2/L3 | 对话模型 | DSH 模型默认 / 自定义回退 | 规则压缩兜底 |
| 事件合并[实验] | 对话模型 | 同上 | 跳过事件摘要 |
| 重要性评估[未来] | 对话模型/规则 | DSH 模型或规则 | 默认 0.5 |

> 嵌入模型唯一无法来自 DSH（DSH 无 embedding 接口）。

## 7. 可观测与实验（用来验证“仿生”是否真的有用）

| 指标 | 用途 |
|---|---|
| 召回命中率 / 用户纠正率 | 验证动态门槛是否提高准确率 |
| 各年龄段的召回占比 | 验证“越久越严格”是否按预期生效 |
| 复述强化后命中变化 | 验证间隔/复述效应（分 B/C/D 类统计） |
| 被动曝光 vs 主动复述比例 | 检查是否出现注入自我循环 |
| 纠正率 / 再巩固完成率 | 验证纠错是否真的改进了记忆 |
| 注入 token / 条数 | 有界理性约束 |
| 整理前后条数与关键信息保留率 | 巩固质量 |
| A/B：旧公式 vs 动态公式 | 科学对照（开关控制，默认开新公式可在配置关掉） |

**实验纪律**：每个参数（τ、strictness、权重）先写假设与失败判据，再用决策日志回放评估；不达预期就回滚。
**默认策略**：新公式默认开启（可一键回退旧公式），参数保守；整理/写入流程不变。

## 8. 已确认决策与完整设计清单

### 已确认

- 功能仿生方向（不是生物复制；参数可测量、可回滚）；
- 动态门槛 + 分层遗忘速度（τ 按层级）；
- 年龄锚点 = 内容发生时间；
- 动态门槛公式与默认参数（由本文定，后续用数据校准）；
- 复述强化按情况分类（A-E 五类，见 3.4）；
- 先完成完整设计，再做功能实现。

### 完整设计清单（实现阶段按此执行）

**1）数据模型（Qdrant payload 新增字段）**

| 字段 | 类型 | 来源/更新 | 用途 |
|---|---|---|---|
| `importance` | 0~1 | 写入时评估；整理可重估 | 门槛补偿、排序 |
| `confidence` | 0~1 | 写入默认 0.7；确认+0.1/纠正−0.2 | 补偿、注入标注 |
| `anchorTs` | epoch | L0=消息时间；L1+=当天/周/月起点 | 动态年龄 |
| `accessEvents` | 数组（最近 20 条 `{type, at, weight}`） | B/C/D/E 事件追加 | 有效复述 |
| `exposureCount` | 整数 | A 事件 +1 | 评估/避免自我强化 |
| `lastAccessAt` / `lastExposedAt` | epoch | 分别更新 | 状态/指标 |
| `needsReview` / `conflictOf` | bool/string | 纠正事件 | 再巩固入口 |

**2）召回流程改造**

- 候选：向量 topN（N=20~50）+ 作用域过滤（global/workspace/session）+ 排除 enhanced；
- 打分：`sim`、`freshness`、`required`、`effective`、`rank`（公式见 3.2）；
- 门控：`effective >= required`；自动召回与工具检索使用不同 base/strictness；
- 排序：`rank = sim×(0.5+0.5×freshness) + 0.15×importance + 0.10×rehearsal + 0.05×confidence`；
- 去重：>0.95 近重复只保留 rank 高者；
- 注入：时间/相对年龄/类型/置信度，注明“可能不完整”；
- 自动召回：`exposureCount++`（不计入强化）；工具检索命中：追加 B 类 accessEvent。

**3）写入/整理链路改造**

- 写入时评估 `importance/confidence`（规则基线；显式保存=1.0/0.9）；
- 自然复述检测：新 L0 与已有信念相似度 ≥0.85 且 kind 匹配 → 追加 C 类事件（异步，不阻塞写入）；
- 睡眠整理产出继承/重估 importance/confidence；`anchorTs` 用内容起点；层级决定 τ；
- 纠正后的 `needsReview` 记忆在整理时优先修订。

**4）配置项（新增，全部有默认值）**

- `recallAgeGateEnabled`（默认开；关=旧公式，可回滚）
- `recallBaseMinScore`（0.42）、`recallStrictness`（0.35）、`recallMaxRequired`（0.90）
- `recallWeightImportance`（0.20）、`recallWeightRehearsal`（0.15）、`recallWeightConfidence`（0.10）
- `decayTauDays`（L0=7/L1=30/L2=180/L3=365，可分别改）
- `rehearsalTauDays`（90）、`rehearsalMaxEvents`（20）
- `importanceRuleEnabled`（默认开）、`rehearsalDetectEnabled`（默认开，自然复述检测）
- 工具检索模式参数：`toolBaseMinScore`（0.30）、`toolStrictness`（0.20）

**5）UI/状态**

- 概览：显示动态门槛开关、τ 参数摘要、平均年龄分布；
- 记忆列表：显示 importance/confidence/有效复述/层级/年龄；
- 召回调试（后续）：显示每条候选的 sim/freshness/required/effective/rank，便于校准；
- 实验面板：可一键关闭动态门槛回退旧公式。

**6）测试（设计阶段先列，实现时逐项）**

- 公式单元测试：年龄/层级/重要性/复述/置信度的边界；
- 行为对照：同 query 下旧公式 vs 新公式的召回集合差；
- 分类测试：A-E 事件分别只影响规定的字段；
- 集成：自动召回不产生 exposure 强化循环（exposureCount 增加但 ranking 不变）；
- 回归：写入/整理/工具/睡眠功能不变；
- 浏览器：配置项、回退开关、列表展示。

**7）发布/回滚**

- 默认开新公式（可配置关回旧公式）；发布前用回放/AB 对比；
- 若命中率/用户纠正率变差 → 一键关 `recallAgeGateEnabled` 回旧行为；
- 参数校准放后续实验，不在第一版追求最优。
